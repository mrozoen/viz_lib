Part One

The seven things costing you marks

Ordered by how many marks each has taken from you. Every "you answered" line below is a real answer you gave.

1. The shared responsibility line

9 misses

Your single biggest leak, and the error is consistent in one direction: you hand things to AWS that belong to you. Encryption, VPC configuration, application scaling and guest OS patching are all yours.

The whole model reduces to one test: if you can configure it or see it, you own it. If it sits below the hypervisor, AWS owns it. Then two exceptions to memorise.

Always yours

  • Guest OS patching on EC2
  • All encryption decisions
  • Security groups & NACLs
  • IAM users, roles, policies
  • Your application & its scaling
  • Your data and who sees it
  • Training your staff

Always AWS

  • Hypervisor & host firmware
  • Hardware & facilities
  • Physical media destruction
  • Edge location management
  • Networking infrastructure
  • Training their staff
  • OS patching on managed services

Shared — only 3

  • Patch management
  • Configuration management
  • Awareness and training
You answered: "encrypting data in transit" as AWS's job · "configuring Amazon VPC" as AWS's job · "patching guest operating systems" as AWS's job · "scaling the web application" as AWS's job · patch management as AWS-only · configuration management as customer-only.
The exception that decides half these questions: OS patching flips with the service. On EC2 it is yours; on RDS, Lambda, Fargate and DynamoDB it is AWS's. Always read the service name in the stem before answering an OS question.

3. Choose TWO technique

14 misses, every one half-right

On all fourteen multi-response questions you have missed, you got exactly one of the two answers right. Never zero. That is not knowledge — you find the obvious answer, then pick a partner that sounds like it belongs with it.

Your second picks: Data Pipeline for deployment, CodeDeploy as compute, EC2 as an edge service, S3 as auto-scalable, "AWS manages all security", ELB across Regions, resource groups as global infrastructure. Every one of them dies instantly when read on its own.

The procedure: read all five options. Mark each one true or false by itself, without looking at the others. Then pick the two you marked true. Never ask "which two go together" — that is the question that makes a good decoy attractive.

5. Hybrid connectivity

5 misses

You reach for Direct Connect too readily. It is a specific product: a dedicated physical line that does not touch the public internet.

  • AWS Direct Connect — dedicated, private, consistent performance, does not use the internet.
  • AWS VPN — encrypted tunnel over the public internet. Cheaper, faster to set up.
  • AWS Storage Gateway — extends on-premises storage into AWS.
  • Amazon VPC — the isolated network in AWS where hybrid connections terminate.
You answered: Direct Connect for "securely connect over the public internet" — the one thing Direct Connect does not do · Direct Connect for "network connectivity in a hybrid architecture" where the key wanted VPC · EBS and Route 53 in the "extend on-premises" question, which is always Direct Connect plus Storage Gateway.

6. Global infrastructure and the edge

6 misses

Two vocabulary facts settle most of these.

  • The global infrastructure is Regions, Availability Zones and edge locations. Nothing else. Not resource groups, not security groups, not AMIs.
  • High availability always means multiple Availability Zones. Not multiple Regions, not a VPC, not global reach.
  • Edge locations serve CloudFront, Route 53, AWS Shield, AWS WAF and Global Accelerator. EC2 and RDS run in Availability Zones, never at the edge.
  • Global services: IAM, Route 53, CloudFront, Organizations. Everything else, S3 included, is regional.
High availability vs fault tolerance: HA means minimal downtime — it recovers. Fault tolerance means no loss of function at all. The words "minimal" and "no" are doing the work in the stem.

7. Distractor recipes you keep falling for

4 misses
  • The absolute. "AWS manages all security in the cloud" — you picked this. Any option containing all, never, eliminates, guarantees or no need to is almost always wrong.
  • Doing it the hard way. You chose "build a service to monitor S3 uploads and remove public ones" over "enable S3 Block Public Access". When AWS ships a switch for the exact requirement, custom tooling is never the answer.
  • The wrong service in the stem. You chose the RDS console to patch databases running on EC2. Read the service named in the scenario before you read the options.
  • The factually false option. "ELB can distribute traffic to multiple AWS Regions" is simply untrue — ELB is regional. You picked it twice, on the same question, five exams apart.

Answer key

Answers and why

Mark the reason as well as the letter. A question you got right for the wrong reason is one you will get wrong on test day.

1BThe customer. On EC2 you have OS access, so you patch it.
2AAWS. RDS is managed: no OS access, so AWS patches it. Questions 1 and 2 are the same task with opposite answers — the service name decides.
3BConfiguration management. The only three shared controls are patch management, configuration management, and awareness and training.
4B, DEncryption decisions and security group configuration are yours. Media decommissioning, inter-AZ networking and host firmware are AWS's.
5BThe customer. AWS provides the certificate service; you decide to use it. Encryption is never automatic on your behalf.
6CHardware maintenance. Scaling your application, patching your images and configuring security groups are all yours.
7CCloudWatch. A number over time plus a threshold is always CloudWatch.
8BCloudWatch. Billing metrics are CloudWatch metrics, so billing alarms are CloudWatch alarms.
9DCloudTrail. Which identity, which API, when, from where.
10AConfig. Resource state over time. CloudTrail would tell you who changed it, not what it became.
11BVPC Flow Logs. Network traffic metadata, accepted and rejected.
12CTrusted Advisor. Its security checks include unrestricted security group access. Inspector scans software for CVEs.
13CPricing / TCO Calculator. They are not on AWS yet, so there is no spend for Cost Explorer to explore.
14BCost Explorer. Visualize, break down and forecast existing spend.
15BBudgets. The word "exceed" plus a notification is always Budgets.
16BDirect Connect. Dedicated, private, consistent, not over the internet.
17BAWS VPN. "Existing internet connection" and "this week" rule out Direct Connect, which is a physical circuit taking weeks to provision.
18B, DDirect Connect for the network link, Storage Gateway for storage. Route 53, CloudFront and EBS are not hybrid extension services.
19CAmazon VPC. Network ACLs are a VPC feature.
20BCloudFront. "Cache" plus "static content" plus "distant users" is the CDN. ElastiCache is in-memory database caching — the word is the trap.
21B, DCloudFront and Shield run at edge locations, as do Route 53, WAF and Global Accelerator. EC2, RDS and EBS live in Availability Zones.
22B, DRegions, Availability Zones and edge locations are the global infrastructure. Resource groups, security groups and AMIs are account-level features.
23B, DRoute 53 and IAM are global, as are CloudFront and Organizations. S3 is regional — buckets live in a Region even though the console lists them together.
24AMultiple Availability Zones. An AZ is one or more data centers; spreading across AZs survives losing one.
25BFault tolerance. "No loss of function at all" is the tell. High availability would say minimal downtime.
26AReduces capital expenditure. Cloud converts capex into variable operational spend, so capex goes down, not opex.
27B, CA is an absolute and false — security in the cloud is yours. D and E are false outright.
28A, BC is false: ELB is a regional service and cannot distribute across Regions. That is the option you have picked twice.
29BS3 Block Public Access. When AWS ships a switch for exactly the requirement, custom tooling is never the answer.
30BEFS. Shared file system, many instances, multiple AZs. EBS attaches to one instance in one AZ.
